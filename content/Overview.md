# Purpose
[UCBUGG](https://www.ucbugg.com/) primarily focuses on 3D Modeling and Animation for cg film, with very little emphasis on VFX or procedural workflows. Creating a Houdini DeCal, or Houdini branch of UCBUGG allows us to explore some deeper and more niche parts of cg, and arguably cooler parts of it.

Houdini is widely used in industry, and is arguably the defacto vfx and procedural tool out there. Creating a Houdini curriculum allows us to look at [[Front Facing/Topics/Proceduralism\|procedural workflows]], explore USD through [[Front Facing/Topics/Solaris]], and see really cool [[VFX\|VFX simulations]], among other things.
# Goals
The goal of this DeCal experience is to most importantly, learn Houdini as a software. We can treat this as an introduction to the software as does UCBUGG. Below are listed things I would like to be able to touch upon in the DeCal (note that this is non-exhaustive and also not strictly necessary)
- [[Front Facing/Topics/Procedural Modeling]]
	- [[L-Systems]]
- [[Front Facing/Topics/COP\|COPs]]
- Simulations

	- [[Front Facing/Topics/FLIP]]
	- [[Front Facing/Topics/Pyro]]
- [[Front Facing/Topics/Solaris]]
- [[Front Facing/Topics/Procedural Animation]]
# Structure
The structure of the course is described in the [[Front Facing/Syllabus]]. The general paradigms will be solo work, open ended projects focused on exploration. Structured a bit like an upper div CS class. As such, it is unsure what the required workload is, but most likely 3 units
# Challenges
Below are listed some challenges associated with creating this course
## Learning Curve
Houdini is an incredibly difficult program to learn
![[Front Facing/attachments/houdiniLearningCurveWithServer.png]]
Creating this DeCal would require us to actually *learn* the software, which is incredibly difficult especially given that we still need to keep UCBUGG alive. Additionally, there comes the problem of what *to* learn. Thankfully, there are various [[Resources\|resources]] that we can use to learn. 
## Interest
Would there be enough interest in this DeCal? Cgi is already pretty niche in Berkeley. Additionally, although [Houdini Apprentice](https://www.sidefx.com/products/houdini-apprentice/) is free and allows full access over the software, it does have a few limitations. Mainly, all renders will be rendered with a watermark (1280x720p), and that you **cannot** export from Houdini in any format, obj, etc.

If we can get Houdini Education installed on the University Computers, which does allow exporting of file formats, no watermark, external renderers, unlimited resolution, etc, then that would allow students to still be able to produce "nice looking" work. But that requires us to strike a deal with SideFX which iirc, or become [certified instructors](https://www.sidefx.com/education/education-programs/instructors/).
### Prerequisites
Houdini requires quite a few prerequisites that I'm not sure if we want to teach from scratch or not. Ideally, this would require prerequisite knowledge of UCBUGG Basic at the minimum. Additionally, probably not required but immensely helpful is knowledge of really basic programming logic (Houdini works a LOT with [[Attributes]]), and linear algebra ([[Front Facing/Topics/VOP\|VOPs]]/Vex use this extensively).
